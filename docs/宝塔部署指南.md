# 宝塔部署指南

## 1. 部署概述

本项目包含两个子工程：
- `server/`：后端服务，使用 Node.js + Express + TypeScript
- `web/`：前端应用，使用 React + Vite

部署方式推荐：
- 后端通过宝塔“Node.js 管理”或 PM2 运行
- 前端通过宝塔“网站”发布静态文件，并使用反向代理将 `/api` 请求转发到后端

---

## 2. 环境准备

### 2.1 服务器要求

- 操作系统：Linux / Windows 均可，宝塔一般运行在 Linux
- Node.js：推荐 18+ 或 20+，建议使用宝塔软件管理安装
- npm：随 Node.js 一起安装
- 额外可选：Redis（如果需要缓存加速，可选）

### 2.2 系统依赖

- Git（用于拉取源码）
- `npm` / `pnpm` / `yarn`，推荐 `npm`

### 2.3 目录结构建议

推荐将项目代码放在：

```
/www/wwwroot/qq_agent
```

目录中应包含：

```
qq_agent/
  package.json
  server/
  web/
  docs/
```

---

## 3. 代码准备

### 3.1 获取项目代码

```
cd /www/wwwroot
git clone <你的仓库地址> qq_agent
cd qq_agent
```

### 3.2 安装依赖

推荐在根目录运行一次安装，宝塔也会在 `server` 和 `web` 下安装依赖：

```
cd /www/wwwroot/qq_agent
npm install
cd server && npm install
cd ../web && npm install
```

如果你使用的是宝塔 Node.js 管理器，也可以直接在 `server` 和 `web` 子目录手动安装依赖。

---

## 4. 后端部署

### 4.1 配置环境变量

后端环境变量文件位于 `server/.env`。

```
cd /www/wwwroot/qq_agent/server
cp .env.example .env
```

编辑 `server/.env`，至少配置以下必需项：

```env
PORT=1076
NODE_ENV=production
JWT_SECRET=your-super-secret-jwt-key-change-this-in-production
NIUMA_ENGINE_URL=http://localhost:1080
DATABASE_URL=file:./database/app.db
CORS_ORIGIN=http://你的域名
REDIS_URL=redis://localhost:6379
UPLOAD_DIR=./uploads
MAX_FILE_SIZE=10485760
```

说明：
- `PORT`：后端监听端口，宝塔反向代理会转发到该端口
- `JWT_SECRET`：务必设置为至少 32 字符的强随机值
- `NIUMA_ENGINE_URL`：连接牛马AI引擎地址，可根据部署实际调整
- `DATABASE_URL`：默认使用 SQLite 文件，路径相对 `server` 目录
- `CORS_ORIGIN`：前端实际访问域名，例如 `http://www.example.com`
- `REDIS_URL`：可选配置，如不使用 Redis 可保留默认值

### 4.2 生成 Prisma Client（如需要）

如果后端运行时报错提示缺少 Prisma client，可以执行：

```
cd /www/wwwroot/qq_agent/server
npx prisma generate
```

### 4.3 构建后端

```
cd /www/wwwroot/qq_agent/server
npm run build
```

构建完成后，生成文件位于 `server/dist`。

### 4.4 启动后端服务

#### 方式A：宝塔 Node.js 管理器

1. 登录宝塔面板
2. 进入“软件商店” -> 安装 Node.js（若未安装）
3. 进入“网站”或“计划任务” -> 新增 Node.js 应用
4. 设置应用目录为 `/www/wwwroot/qq_agent/server`
5. 入口文件填写 `dist/index.js`
6. 环境变量填写 `NODE_ENV=production`、`PORT=1076` 及其他必要变量
7. 启动应用

#### 方式B：PM2 运行

如果服务器支持 PM2，可执行：

```
cd /www/wwwroot/qq_agent/server
npm install -g pm2
pm2 start dist/index.js --name qq_agent_server --env production
pm2 save
```

> 注意：生产环境下不要使用 `--watch`，否则 PM2 会监控 `dist` 目录的文件变化并导致进程不断重启。

### 4.5 后端数据库与目录权限

确保以下目录可写：

- `server/database`
- `server/uploads`

如果没有目录，请手动创建：

```
mkdir -p /www/wwwroot/qq_agent/server/database
mkdir -p /www/wwwroot/qq_agent/server/uploads
chmod -R 755 /www/wwwroot/qq_agent/server/database
chmod -R 755 /www/wwwroot/qq_agent/server/uploads
```

## 5. 前端部署

### 5.1 生成前端静态文件

```
cd /www/wwwroot/qq_agent/web
npm run build
```

构建结果目录为 `web/dist`。

### 5.2 前端配置

前端默认使用相对路径 `/api` 发起接口请求。只要前端和后端部署在同一个域名下，并且宝塔配置了 `/api` 反向代理，通常无需修改。

如果你要使用不同域名或端口，请在 `web/.env` 中启用 `VITE_API_BASE`：

```env
VITE_API_BASE=http://后端域名:1076/api
```

然后重新构建前端：

```
npm run build
```

### 5.3 宝塔网站设置

1. 登录宝塔面板
2. 进入“网站” -> 添加站点
3. 网站目录填写 `/www/wwwroot/qq_agent/web/dist`
4. 绑定域名并配置 SSL

### 5.4 反向代理配置

如果前端和后端同域名部署，建议在宝塔网站的“反向代理”中添加规则：

- 代理目录：`/api`
- 目标URL：`http://127.0.0.1:1076`
- 发送域名：`127.0.0.1`

> 注意：不要把目标URL写成 `http://127.0.0.1:1076/api`，否则根据宝塔代理规则可能导致路径重复或后端收到错误路由。

如果使用 Nginx 配置，可参考：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:1076;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location / {
    root /www/wwwroot/qq_agent/web/dist;
    try_files $uri $uri/ /index.html;
}
```

## 7. 常见问题

### 7.1 后端启动失败

- 检查 `server/.env` 是否存在且 `JWT_SECRET` 已设置
- 检查 `server/database` 和 `server/uploads` 是否具有写权限
- 如果报 `Prisma` 相关错误，执行 `npx prisma generate`

### 7.2 前端页面只能加载静态资源，API 请求 404

- 检查宝塔反向代理是否已正确配置 `/api` 到后端端口
- 检查前端构建是否使用相对路径 `/api`
- 确认后端服务已正常运行

### 7.3 前端访问 `CORS` 问题

- 如果前端与后端不在同一个域名，必须修改 `server/.env` 中 `CORS_ORIGIN` 为前端域名
- 若前端使用 `VITE_API_BASE`，请确保后端允许该域名

---

## 8. 部署验证

1. 后端访问 `http://127.0.0.1:1076/health`，应返回 `success: true`
2. 前端域名访问首页，页面能正常打开
3. 登录或注册功能能正常访问
4. 检查浏览器控制台是否有 API 404 或跨域错误

---

## 9. 生产优化建议

- 推荐使用 `NODE_ENV=production`
- 后端建议使用 PM2 或宝塔 Node.js 管理保持进程常驻
- 使用 SSL 保护域名
- 将 `JWT_SECRET` 和 `NIUMA_ENGINE_URL` 设置成生产值
- 服务器性能不足时可考虑接入 Redis
